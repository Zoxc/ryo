# Part B. x86-64 semantics for the emitted subset (L2)

The target level: the machine code ryo emits, AOT and JIT, read from bytes. Provenance does
not exist here: memory is flat bytes, and every relation into L2 erases it
([reduced.md](reduced.md), [plan.md](plan.md) §1.3).

### B.1 The AOT subset

ryo's AOT machine code is a closed, canonical set. Everything the AOT encoder emits is an
`asm::x86::Item` (`vm/bytecode/src/asm/x86.rs`, ~45 forms):

- **Prologue/epilogue**: `PushRbp`, `WinPrologue`, `WinEpilogue` (PE), `SubRsp`, `AddRsp`,
  `Leave`, `Ret`
- **Register setup**: `SetReg` (`xor r32,r32` / `mov r32,imm32` / `mov r64,simm32` /
  `mov r64,imm64`), `Lea(reg, rip+…)`, `LeaTable`, `Mov`, `LoadRip`
- **Calls**: `Call(rel32)`, `CallMem([rip+…])`, `CallRax`, `CallMemRax`, `CallR11(disp8)`,
  `JmpRax`, `Jmp(rel32)`, `Branch{Always|Z|Nz|…, rel8|rel32}`
- **Tests and tables**: `TestAl`, `TestRax`, `TestM8`, `LoadTableEntry`, `AddRaxRcx`,
  `TableEntry`, `Ud2`, `Int3`, `Nop(1..9)`
- **Counters**: `CtrSub(imm8)` (`sub qword [rip+…], imm8`)
- **Inline arithmetic**: `Ld{w,sx}`, `St`, `StImm`, `LeaM`, `Alu{add,or,and,sub,xor,cmp}` on
  r/m, `AluImm`, `Imul`, `ImulImm`, `Shift{shl,shr,sar}` by imm8, `Setcc` to memory
- **SSE**: `Sse` (`movss`/`movsd`/`movups` to and from frame slots, `xmm0`–`xmm7`),
  `Movd`

Outside `Item`:

- the OSR code of today's JIT (`asm/osr.rs`): `pop rcx`, loads/stores of 1/2/4/8 bytes
  between `rax` and `[rdx|rbp|rsp + disp32]`, `lea rsp`, the dispatcher's `movsxd` table
  jump, probe calls
- the JIT entry prefix (`lea r11,[rip+code]; mov [rsp],r11; ret`)
- the trip stubs (`lea r11,[rip+rec]; mov eax,N; call [r11+16]; jmp`)
- the registry constructor (`lea rdi,[rip+images]; mov esi,n; jmp ryo_vm_register`,
  `objfile.rs` `add_registry_ctor`)

Those are added as `Item`-like forms in Lean (`Ryo/X86/Extra.lean`).

### B.2 Lean modules

| Module | Contents |
|---|---|
| `Ryo/X86/Item.lean` | `Reg`, `Cond`, `W`, `M` (memory operand), `Rm`, `Alu`, `Sh`, `Item` (mirror of `x86.rs`, generated or hand-written with a test that both enumerate the same forms) |
| `Ryo/X86/Encode.lean` | `Item.encode : Item → (pos : BitVec 32) → List UInt8 × List Reloc` (Intel SDM encodings, ModRM/SIB/REX, shortest immediates), as Rust's `Item::write`: relocated fields are zeros, named by a `Reloc` (position, `Ref`); `link` patches them for code at a known address |
| `Ryo/X86/Decode.lean` | `decodeItem : Cursor → Option (Item × Nat)` accepting only canonical encodings (Rust's `Cursor::item`, with its `Fields` and `sp_frame`). `encode (decodeItem b) = b` outside the relocated fields holds by construction (a candidate is accepted only if it re-encodes to the bytes); `decodeItem (encode i) = some i` for `Item.wf` items is tested (the Rust encoder's vectors, ~93k generated items). Relocated fields: named (from the object's relocation list) or, for linked code, resolved through a `LinkMap` (a total function from addresses to `Option Ref`) |
| `Ryo/X86/State.lean` | `Regs` (16 GPRs as `BitVec 64`), `rip`, flags `CF ZF SF OF` (each `Option Bool`: `none` where the SDM leaves it undefined; reading it faults; PF/AF not modeled), `xmm0..15 : BitVec 128`, flat `Mem : BitVec 64 → UInt8` with little-endian `read`/`write`, and a serializable `State.View` |
| `Ryo/X86/Extra.lean` | the forms outside `Item` (§B.1) as `XItem`s with encode, decode and semantics; `osrCode` ports `osr_code` |
| `Ryo/X86/Exec.lean` | `Item.exec : Ctx → Item → State → Except Fault State` per Intel SDM (`Ctx`: the function's address and where each `Ref` lives), including flag semantics for `add/sub/cmp/test/and/or/xor/imul/shl/shr/sar`, `setcc`, `jcc` conditions, `movzx`/`movsx`, `leave`, `ret`. Calls and returns are plain: push/pop at `rsp` |
| `Ryo/X86/Env.lean` | the environment: a call to an address outside the function is resolved by a `LinkMap`: handler `h` → contract `H h`, `ryo_probe_stack` → contract, symbol slot `s` → external callee (convention), image function → function code, trip entry points → the trip contract ([jit.md](jit.md) §E.2). Unwinding: an external callee may return "unwinding with exception object e"; the unwinder lands at the call site's landing pad from the LSDA, restoring the registers the FDE describes (the FDE rows are checked, [aot.md](aot.md) §C4) |
| `Ryo/X86/Plus/…` | L2+ for the SSA JIT (§B.4): the extended item set, a **generic** decoder, their semantics |

### B.3 Validating the x86 semantics itself (it is trusted)

- **Co-simulation on the CPU**: a Rust test harness (`vm/bytecode/tests` or a new
  `lean/harness` crate) executes random single `Item`s and random inline runs from random
  register and memory states (mapped page, state dump after the item). It compares the
  result with `ryo-lean exec-item` on the same input (JSON over a pipe). This covers flags,
  partial-register writes (`movzx`, 32-bit zero extension, `setcc`), and REX forms for
  `sil`/`dil`/`r8`–`r11`. The same harness covers L2+.
- **Encodings**: compare `Item.encode` with the Rust encoder for all items in the asm round
  trip tests, and with an independent disassembler (`objdump -d` / `llvm-mc
  --disassemble`) over the corpus objects.
- Optional later: cross-check against a published x86 model (ACL2 `x86isa`, Sail x86, the K
  framework x86-64 semantics).

### B.4 L2+: the SSA JIT's forms

The SSA tier of the JIT ([jit.md](jit.md) §E.3) emits register-allocated code: values in any
GPR across instructions, addressing modes `[b+i*s+k]`, `cmp`/`jcc` and `add; jo` fusion,
`cmov`, `shl r,cl`, `lea` arithmetic, callee-saved saves and restores, `cpuid`-dependent
`popcnt`/`lzcnt`/`tzcnt`/BMI, and SSE in any `xmm`. L2+ is:

- `Ryo/X86/Plus/Item.lean`: an extended item set, a superset of `Item` (so AOT forms keep
  their semantics). Each form carries the CPU feature it needs.
- `Ryo/X86/Plus/Decode.lean`: a **generic** decoder (prefixes, REX, ModRM/SIB, the opcode
  maps of the forms in the set) that accepts any encoding of those forms, not only the
  canonical one. Theorem: `decode` is a left inverse of `encode` and every accepted byte
  string re-encodes to itself (`encode (decode b) = b`), so decoding is unambiguous.
- `Ryo/X86/Plus/Exec.lean`: semantics, with the feature set as a parameter: a form whose
  feature is absent faults (`#UD`).
- The co-simulation harness of §B.3 runs over every form, under the CPU's features.

The constraint on the JIT is not "keep the output canonically decodable" but: *every form
the JIT emits is in L2+, and the JIT logs its post-allocation IR with per-block item
boundaries* ([jit.md](jit.md) §E.4).
